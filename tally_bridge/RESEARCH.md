# BizAnalyst feature research

Reviewed 19 October 2026. The BizAnalyst website and Tally's official documentation host were blocked by this development environment's destination policy. Their domains were added to the cloud configuration draft; saving that draft does not apply it. The research below uses separately published, publicly accessible GitHub documentation. No third-party implementation code was copied.

BizAnalyst documentation in the `siliconveins/bizanalystdocs` repository is dated **2017**. It supports historical feature comparisons, not claims about today's prices, plans, feature availability or Tally Prime compatibility.

For XML protocol cross-checking, consulted the [TallyConnector documentation](https://github.com/Accounting-Companion/TallyConnector/blob/master/docs/Readme.md), its published request models and synthetic XML fixtures. These are secondary sources and do not replace testing with the installed Tally Prime version. The sales XML itself comes from this repository's existing, business-specific `tally/index.html` exporter and is covered by semantic parity tests.

For the 1.0.1 ledger-report review, public integration examples differ on the selector: [anythingmcp's request tests](https://github.com/HelpCode-ai/anythingmcp/blob/67651834b47f3d2fad425b0ebb6404d20b2a4a9e/packages/backend/src/adapters/in/tallyprime.live.spec.ts) use `LEDGERNAME`, while [Tally-MCP-Server's template](https://github.com/vaijaaaaa/Tally-MCP-Server/blob/0321e9dd277cb98b1239ce2b9b8cdd974dc18456/templates/ledger-vouchers.xml.njk) uses `SVLEDGERNAME`. The bridge sets both to the same escaped ledger name, verifies that name against the live company's Ledger collection, and includes the company and period explicitly. These community examples are protocol cross-checks, not proof of compatibility with the user's installed Tally version; the first live report remains an acceptance check.

## Background recovery and Windows packaging (1.0.2)

- [Tally command-line parameters](https://help.tallysolutions.com/tally-developer-command-line-parameters/), under **Tally Command Line Parameters** (distinct from the Developer application's parameters), documents `/LOAD:<Company Number>` and `/NOINILOAD`, with an example loading company `00009`. These are used to start a stopped Tally process minimized. `/NOGUI` is documented for running an action and exiting, so it is **not** treated as a persistent headless XML service.
- Optional numeric-company discovery follows the `@@SetCmpNumStr` formula demonstrated by [Accounting-Companion/TallyConnector Company.cs](https://github.com/Accounting-Companion/TallyConnector/blob/03c7f4f53914bcbf017849c8e268154cffcfd76e/src/TallyConnector.Models/Base/Company.cs). That community implementation is a cross-check, not proof of compatibility. Discovery failure is safe and requires the number to be supplied once; the company GUID still gates every sync.
- The user confirmed Windows stays signed in and company selection requires no credentials. This release therefore uses the current interactive Windows account, not a Session 0 service, stored Windows password or automatic Windows login. Tally remains the accounting engine.
- A Defender block was reported for 1.0.1. The official published executable matches SHA-256 `4f58c9eadfeb5c3e12e52e69cc633a9f867af217ca7ca2795eface525d615a91`. That establishes identity, not a false-positive conclusion. The exact detection remains necessary for attribution; no antivirus bypass is provided.
